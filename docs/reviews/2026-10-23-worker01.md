# Worker 01：报名原子性与截止校验

日期：2026-10-23。仅修改报名函数及本地检查，未读取凭证、未访问生产报名资料、未部署。

## 修复

- `submitVolunteerRegistration` 在服务端检查平台 OPENID、必要文本、手机号/学号、可选年龄；年龄未提供时不生成年龄，提供时保存 `volunteerAge` 快照；移除完整事件与个人资料日志。
- 同活动的当前 `volunteer_registrations.task_id` 与历史 `registrations.route_id` 均分页读取，排除已拒绝/取消状态；二者共同占额，同学号（兼容 `student_id`）或同 OPENID（兼容 `openid`）阻止重复。
- 先读取活动 `registration_revision`，再查询两表。事务重新读取活动，检查版本未变及最新启用/删除状态、截止时间、配额，原子插入报名、写真实报名总数并将版本加一。人数写到活动实际类型决定的 `volunteer_count` 或 `current_count`。
- 事务回调禁止内部重试（第二参数 `0`），版本变化及实际数据库冲突均在外层最多重试 5 次，每次重新查询两表。兼容 wx SDK 将冲突包装为 `errCode`、消息带 `TransactionConflict` 的错误形状。持续竞争给出稍后重试，不超额接受。
- `YYYY-MM-DD HH:mm` 明确按上海时区解析，到该分钟即截止；历史只有日期的值在该日结束时截止。无效截止值拒绝报名。

## API 与一致性依据

- 官方：[CloudBase 事务操作](https://docs.cloudbase.net/database/transaction)。事务支持文档 get/add/update 等原子操作；不支持 `where`，单事务上限 100 操作、30 秒。
- 本地只读核实：`cloudfunctions/getRoutes/node_modules/wx-server-sdk/package.json` 为 `2.6.3`；其 `index.js` 的 `Transaction`/`runTransaction` 包装转交数据库事务，`CollectionReference.add({data})` 返回 `_id`。底层 `@cloudbase/database/src/transaction/index.ts` 确认回调结果可返回、失败自动回滚，`times=0` 禁止自动重试。
- 同 SDK 的数据库错误包装会将错误 code 映射至数值 errCode；本地 `@cloudbase/node-sdk/test/database/unit/transaction.test.ts` 包含真实冲突标识 `ResourceUnavailable.TransactionConflict`，因此不能仅判断 `error.code`。
- 当前事务只执行活动 doc get、单条报名 add、活动 doc update，避免虚构事务 where。两表分页查询在事务外，通过活动版本校验证明读取期间没有已提交的成员变化；并发提交竞争同一活动文档，由事务冲突检测阻止同时通过。

## 联动发布要求

所有报名新增、删除、恢复、影响占额状态变更必须在同一事务中更新同一个活动文档的 `registration_revision`。拒绝流程与删除流程由其他 worker 改造；删除须先写 `deleting`/`enabled=false` 并增加版本，再清理两表。

父任务已发现线上存在仓库原未收录、无当前页面调用的 `submitRegistration` 旧入口；它也必须同步关闭或改造，否则会绕过本一致性协议。发布先关闭旧入口，再发布拒绝/删除，最后发布当前报名函数。保留生产备份和父任务统一发布记录。

历史重复记录不擅自删除，每条有效记录保守占一个名额；超过现配额时拒绝新增。真实计数在每次成功报名时落盘校准，读取展示由已有两表统计承担；没有执行全库迁移。若有人绕过云函数直接改报名集合而不更新活动版本，本协议不能保证一致性，应限制此类写入。

## 本地验证

`node --check cloudfunctions/submitVolunteerRegistration/index.js` 通过。

`node tests/registration-atomic.test.js` 共 9 组通过。测试加载实际函数代码，使用提交时读版本校验、冲突与整笔回滚的内存数据库，并禁止事务 where：

1. 20 个并发请求、5 个名额恰好接受 5 个，真实计数和版本均为 5。
2. 同学号不同 OPENID、同 OPENID 不同学号并发时各只接受一个。
3. 超 100 条分页、两表历史占额、历史别名判重、inactive 排除与实际活动类型计数。
4. 上海时区同日分钟截止、日期历史值、停用/删除/满额/无效配置拒绝。
5. 拒绝与报名快照并发时重取两表，名额释放和计数准确。
6. 活动新状态在事务内重查；计数写失败不遗留报名。
7. 持续版本竞争只尝试 5 轮。
8. wx SDK 包装的冲突重试后重新计入刚提交的历史记录。
9. 平台身份、年龄快照和缺失年龄不伪造。

这些是本地 MVCC 模拟验证，不等同生产数据库实测。Cloud 部署与部署后核验由父任务统一执行；网页与小程序界面上传未涉及本 worker。
